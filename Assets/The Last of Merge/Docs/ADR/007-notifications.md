# ADR 007: архитектура внутриигровых оповещений
  
## Статус
В процессе обсуждения
  
## Контекст
Нужны оповещения, так называемые всплывающие окна.
Реализация может быть совершенно разная, данные
могут быть совершенно разными.
  
## Рассмотренные варианты
ИИ предложил свой вариант с созданием простых классов для описание внешнего вида оповещения. Но такое не передашь через сервер. Вдобавок никак не передашь новую картинку, нужно будет перегружать целое приложение. Однакое, есть использовать для темплейтов оповещений Addressables, становится очень просто засунуть почти что угодно в содержимое оповещения. От сервера же лишь требуется передать клиенту (по запросу) очередь не показанных оповещений.
  
## Решение
Для простоты первоначальной архитектуры следует отделить клиентскую часть и серверную.
На клиенте есть очередь оповещений, они могут накладываться друг на друга.
Когда все закрыты, закрывается и глобальное затенение.

Используем Addressables для поставки необходимых оповещний без перезагрузки билдов в сторы. Плюс, используем конкретные уже переведённые строки прямо с сервера (из бандлов по факту), и на конечном устройстве выбираем нужную строку исходя из языка игры.

- NotificationManager - отвечает за показ нотификаций. Ему передаётся шаблон (ScriptableObject), а также параметры для текста. Предоставляет доступ для регистрации обработчиков нажатия на кнопки внутри оповещений.
- NotificationContainerView - отвечает за отображение вида оповещений.
- NotificationView - отвечает за конкретное отображение оповещения.
- NotificationData - шаблон (ScriptableObject), исходя из которого NotificationView собирает себя и заполняет внешний вид.

Таким образом, клиент сможет показывать новые оповещения, просто запрашивая в начале игры новые бандлы (как это всегда и делается). Плюс остаётся возможность параметризировать локальные оповещения (и возможно, если подумать немного, то и готовые строки можно будет параметризировать как-нибудь).
